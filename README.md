# سامانه استخدام گل‌پخش اول

نیازمندی: Node.js 22.5 یا جدیدتر (پیشنهاد: Node.js 24).

```powershell
npm install
npm run dev
```

سامانه در http://localhost:3000 و پنل مدیریت در http://localhost:3000/admin در دسترس است. برای نسخه production از `npm run build` و سپس `npm start` استفاده کنید. پایگاه داده SQLite در فایل `ats.sqlite` کنار پروژه ساخته می‌شود و باید از آن نسخه پشتیبان تهیه شود. آگهی‌ها از SharePoint دریافت می‌شوند؛ آگهی‌های نمونه قدیمی فقط برای نمایش سوابق درخواست‌های قبلی نگهداری شده‌اند. مدیر از پنل مدیریت می‌تواند رزومه‌ها را دریافت کند و وضعیت هر درخواست را تغییر دهد.

رمز مدیریت در فایل خصوصی `.env.local` و در متغیر `ADMIN_PASSWORD` قرار دارد. این فایل همراه مخزن منتشر نمی‌شود. برای تغییر رمز، مقدار آن را با یک رمز قوی و منحصربه‌فرد جایگزین کنید و سرور را دوباره اجرا کنید. در محیط استقرار نیز باید همین متغیر را به صورت محرمانه در تنظیمات سرور تعریف کنید. اگر فایل تنظیمات محلی وجود ندارد، آن را بسازید و یک خط به شکل `ADMIN_PASSWORD=رمز-قوی` در آن قرار دهید.

این نسخه برای استقرار عمومی نیازمند تکمیل تنظیمات عملیاتی از جمله HTTPS، محدودسازی تلاش‌های ورود، بازیابی رمز، سیاست نگهداری اطلاعات و ذخیره‌سازی و پشتیبان‌گیری مناسب است. فایل پایگاه داده و رمز مدیریت را منتشر نکنید.

## اتصال به SharePoint داخلی

آگهی‌ها از API لیست شیرپوینت و فقط با وضعیت‌های «انتشار آگهی» یا «در حال بررسی رزومه ها» دریافت می‌شوند. نام کاربری و رمز را صرفاً در تنظیمات محرمانه سرور قرار دهید؛ آن‌ها را داخل کد یا ایمیج قرار ندهید. سرویس ATS باید از شبکه داخلی یا VPN بتواند نام `gpasharepoint` را resolve کند و به سرور دسترسی داشته باشد. اتصال مستقیم HTTP رمزنگاری‌شده نیست؛ در صورت امکان از HTTPS معتبر استفاده کنید.

در فایل `.env` سرور مستقل مقادیر زیر را همراه سایر تنظیمات موجود قرار دهید. نشانی API ارائه‌شده برای شیرپوینت به‌صورت پیش‌فرض تنظیم شده است. متغیر `SHAREPOINT_JOBS_URL` فقط در صورت تغییر نشانی لازم است؛ نشانی سفارشی را در تک‌نقل‌قول بگذارید تا Compose عبارت `$filter` را تغییر ندهد:

```dotenv
SHAREPOINT_USERNAME='DOMAIN\username'
SHAREPOINT_PASSWORD='رمز حساب سرویس'
SHAREPOINT_AUTH=ntlm
```

احراز هویت پیش‌فرض NTLM است؛ متناسب با تنظیمات سرور می‌توان `negotiate` یا `basic` انتخاب کرد. Basic فقط روی HTTPS استفاده شود. حساب سرویس باید دسترسی خواندن لیست را داشته باشد. پس از تغییر فایل Compose و تنظیمات، کانتینر ATS را مجدداً ایجاد کنید. این اتصال نیازمند `curl` است که در ایمیج نصب می‌شود و پاسخ XML یا JSON شیرپوینت را می‌پذیرد.

آگهی‌ها حداکثر هر ۶۰ ثانیه با مراجعه به سامانه به‌روز می‌شوند. هنگام قطع ارتباط، آخرین آگهی‌های ذخیره‌شده با هشدار نمایش داده می‌شوند و ثبت درخواست جدید تا تأیید وضعیت آگهی متوقف می‌شود. عنوان درخواست‌های ثبت‌شده حفظ می‌شود. تغییر فهرست یا سایت SharePoint پس از ثبت درخواست‌ها نیازمند برنامه‌ریزی مهاجرت شناسه‌هاست.

## ساخت و اجرای Docker

روی دستگاهی که Docker دارد، در پوشه پروژه ایمیج را بسازید:

```bash
docker build -t golpakhsh-ats:latest .
docker save -o golpakhsh-ats.tar golpakhsh-ats:latest
```

فایل ایمیج و فایل `compose.yaml` را به سرور منتقل کنید. روی سرور، در پوشه‌ای که فایل Compose قرار دارد، ایمیج را بارگذاری کنید:

```bash
docker load -i golpakhsh-ats.tar
```

در همان پوشه، یک فایل محرمانه به نام `.env` بسازید و رمز قوی مدیریت را در آن قرار دهید:

```dotenv
ADMIN_PASSWORD=یک-رمز-قوی-و-منحصربه‌فرد
```

سپس سرویس را اجرا کنید:

```bash
docker compose up -d --no-build
docker compose logs -f
```

برنامه روی پورت ۳۰۰۰ سرور گوش می‌دهد. برای دسترسی عمومی یک reverse proxy با HTTPS در مقابل آن قرار دهید؛ کوکی‌های ورود در حالت production به HTTPS نیاز دارند. برای توقف سرویس از `docker compose stop` استفاده کنید.

پایگاه داده و فایل‌های رزومه در volume با نام `golpakhsh-ats-data` نگهداری می‌شوند و داخل ایمیج قرار نمی‌گیرند. از این volume به‌طور منظم پشتیبان بگیرید. حذف volume داده‌ها را پاک می‌کند. انتقال ایمیج به‌تنهایی داده‌های قبلی را منتقل نمی‌کند.

برای انتقال داده‌های موجود، ابتدا برنامه مبدأ را متوقف کنید تا فایل SQLite در حال تغییر نباشد و فایل `ats.sqlite` را در پوشه Compose سرور قرار دهید. پیش از اولین اجرای سرویس، volume را بسازید و فایل را در آن کپی کنید (دستورهای زیر برای Linux هستند):

```bash
docker volume create golpakhsh-ats-data
docker run --rm -v golpakhsh-ats-data:/data -v "$(pwd):/backup:ro" --entrypoint sh node:24-bookworm-slim -c 'cp /backup/ats.sqlite /data/ats.sqlite && chown 1000:1000 /data/ats.sqlite'
docker compose up -d --no-build
```

این دستور فایل موجود در volume را جایگزین می‌کند؛ آن را فقط هنگام انتقال اولیه و پیش از ثبت اطلاعات جدید اجرا کنید.
